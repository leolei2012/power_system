## 执行结构

硬件执行 PWM、采样触发、QEP 计数及故障封锁；高优先级中断执行采样处理、快速控制与占空比提交；ThreadX 负责运行状态、慢环、通信、遥测和维护。20 kHz 等快速控制不通过系统 tick 或软件定时器调度，也不每周期唤醒线程。

两路逆变各支持交流源/电机控制模式，一路 PFC 支持 Boost/Vienna 板型。算法模式与功率板配置在停机状态选择。第一阶段先跑通一路逆变，再扩展两路，最后增加 PFC；最终保留单 MCU 同时控制三套功率级的目标。

电机侧先 V/f，再 FOC；交流源先开环 SVPWM，再验证电压闭环。采样标定、限幅、故障状态和硬件驱动层共用。软件模式不能改变接口电平、隔离边界或尚未确定的硬件能力。

## 制动控制分工（2026-11-01 已确认）

用户确定制动由 controller 软件控制：分别读取所属 inverter 的母线电压，通过独立 BRAKE_1 / BRAKE_2 输出控制各板制动驱动及 MOS。inverter 本地硬件仍独立完成 65 V 过压和瞬时 ±20 A 过流锁存关断三相桥；制动支路不增加自主电压门限比较控制，不占用剩余比较器通道作为新增自动制动功能。

同日已确认 inverter 制动驱动为 TI UCC27517DBVR，稳压 12 V 供电；BRAKE_1/2 按 3.3 V 高有效、默认低请求关闭。软件初始化先保持低输出，再配置复用/时基；板端默认下拉、输入/栅极外围以及 MCU 复位期间的实际关断行为仍需验证。

- 各路独立保存合法的制动配置、迟滞状态、母线样本时间戳及外接电阻安装/启用配置。安装标志为人工配置，不代表硬件自动识别。配置在停机状态经校验后整体发布到快速路径，通信线程不直接操作制动输出。
- 60 V 工况名义目标为上升至 62 V 开启、下降至 61 V 关闭；1 V 迟滞带内保持前一合法请求状态。启动默认无请求；其他供电工况门限另定，不能沿用 62/61 V 作为统一参数。
- 制动电压判断和输出更新纳入有界的高优先级快速采样/控制路径，不交给 ThreadX 1 ms supervisor 检查或软件定时器。supervisor 管理授权、诊断和配置。母线 ADC 采样率、滤波、判断执行率、输出方式（开关或 PWM）、制动 PWM 频率及最大允许延迟仍需设计；不得仅因三相桥为 20 kHz 就认定制动控制时序已经满足。
- 将 ADC 采样间隔/数据年龄、模拟及数字滤波、最长中断屏蔽、处理和输出提交延迟、驱动/MOS 动作时间计入最坏响应。结合母线电容和最大回馈功率计算电压爬升裕量，再测量验证；无损耗简化下可用 Δt = C×(V_trip²−V_on²)/(2×P_regen) 估算可用时间，最终用误差最坏角点和有效电容校核，不能直接按名义值作保证。
- 制动状态与电机 RUN/ENABLE 分开管理；正常停机或三相桥故障后，在供电、采样及制动支路自身健康且配置允许的条件下，仍继续执行制动判断。采样超时、MCU 复位/卡死、制动过热/支路异常的具体处理需设计；不能无条件“所有故障关所有 PWM”而误关仍需耗能的制动支路，也不能无条件强制制动常开。
- 检查 MCPWM FAIL/输出屏蔽对 CH3P 的作用范围，确保三相桥硬件关断不误封锁 BRAKE_1/2；若芯片无法按需要区分，需重新评估输出资源或驱动封锁配置，不将现有静态引脚分配当作已验证实现。

本次仅确定控制分工，不表示软件已实现或实时性已通过。制动耗能依赖 MCU、有效采样、辅助供电及实际安装的电阻；65 V 硬件关断三相桥不等于能够吸收再生能量。新增处理时间、状态和缓冲需计入本文已有 CPU/SRAM 预算，无新增线程或 DMA 通道的默认承诺。

## ThreadX 线程候选

线程优先级数值越小越高；这里的优先级与 NVIC 中断优先级是两套独立编号。全部线程栈和内核对象静态分配，初始化后不创建/销毁线程、不使用运行时通用堆。独立优先级、无时间片，初版不使用抢占阈值优化。栈容量是起始预算，不是官方最小值或已验证大小。

| 线程 | 优先级 | 栈 | 触发/周期 | 职责 |
| --- | ---: | ---: | --- | --- |
| ThreadX timer（内核） | 2 | 1024 B | tick/定时器事件 | 超时管理；回调只发布短事件 |
| supervisor | 3 | 1536 B | 事件＋1 ms 检查 | 启停状态、故障记录、母线/温度监控、健康检查与喂狗授权 |
| outer_loop | 5 | 2048 B | 1 ms 候选 | 两路速度/位置等慢环、PFC 母线外环、给定斜坡；实际环频率另定 |
| communication | 12 | 2048 B | UART/CAN 事件 | 协议解析、命令校验、参数请求；不直接改 PWM |
| telemetry | 20 | 1536 B | 10～100 ms 候选 | 抽取状态、限带宽发送、故障上传 |
| service | 24 | 1024 B | 事件＋低频巡检 | 参数持久化、LED、诊断、维护 |
| **合计** | | **9216 B** | | 5 个应用线程＋1 个内核 timer 线程 |

1 ms 是慢环调度候选，存在中断和调度抖动；使用实际时间戳计算 dt，并检测延迟/漏周期。不能把 tx_thread_sleep(1) 当成精确的 PWM 同步时钟。两个逆变慢环共用一条线程，避免为每个外设再增加线程。故障由硬件和中断先封锁，supervisor 随后处理，不能等待 1 ms 才关断功率管。

ThreadX 默认优先级数量、timer 线程默认值和 BASEPRI 选项见[官方 Cortex-M4 GNU 端口](https://github.com/eclipse-threadx/threadx/blob/master/ports/cortex_m4/gnu/inc/tx_port.h)；本表是项目选择，timer 优先级 2 需显式配置。

## 中断与内核屏蔽边界

采用官方 Cortex-M4 端口候选，编译器尚未锁定。GNU 路线为 ports/cortex_m4/gnu；若使用 Keil/AC6，选对应官方端口并重新核对 ABI、启动文件和 FPU 保存。正式依赖应锁定发布 tag 和提交号，不能直接用移动的 master 分支作为可复现版本。

拟启用 TX_PORT_USE_BASEPRI，使内核临界区不屏蔽快速控制中断。该宏及 TX_PORT_BASEPRI 必须同时进入 ThreadX C 和汇编编译；只给应用 C 文件定义无效。移植仍须审查 BSP/库中 PRIMASK 全局关中断的最长时间，BASEPRI 不能消除其他代码的全局屏蔽。

设 N 为芯片实际实现的 NVIC 优先级位数，需由厂家 CMSIS/SDK 与寄存器读回确认。候选内核屏蔽分界为逻辑优先级 8，TX_PORT_BASEPRI = 8 << (8-N)，前提是 N 足以表示该分界。配置抢占优先级分组后统一换算，不能把逻辑优先级 8 直接写成 BASEPRI 原始值。

| 中断类别 | 逻辑优先级候选 | 是否调用 ThreadX |
| --- | ---: | --- |
| MCPWM FAIL/关键故障记录 | 1 | 否；短时保存首故障并封锁 |
| ADC 完成/快速采样、共享 DMA IRQ（若承载 ADC） | 2 | 否；读取完整帧后执行快速控制 |
| 必要的 PWM/采样调度事件 | 3 | 否；不按 PWM 边沿进入中断 |
| 控制用 SPI 完成/QEP 索引等 | 4 | 否；发布带时间戳的数据 |
| UART、CAN、一般 EXTI | ≥8，例如 10/12 | 仅使用官方允许的 ISR API，且不等待 |
| SysTick | 最低优先级的前一级 | 内核 tick；必须落在 BASEPRI 屏蔽范围内 |
| PendSV | 实现的最低优先级 | 专供 ThreadX 上下文切换 |

高于屏蔽分界的中断在内核临界区仍可执行，因此不得调用 tx_event_flags_set、tx_queue_send 等内核服务，也不得操作内核对象。故障、采样和 SPI 快路径通过有界缓冲/原子状态交接，线程按周期取走。需要即时线程通知时，应由独立且可被内核屏蔽的延后处理路径执行，不能挪用 PendSV 或再造一个 SysTick_Handler。

共享 DMA 只有一条 NVIC 入口，应先处理 ADC 通道，再处理通信通道，所有分支均按该 IRQ 的高优先级规则执行，不可在通信分支调用 ThreadX。RTOS 初始化例程可能重写系统异常优先级，须在最终移植代码中统一设置并读回核对。

## 时钟、FPU 与实时预算

系统主频候选为 192 MHz，ThreadX tick 候选为 1 kHz。TX_TIMER_TICKS_PER_SECOND 仅描述内核 tick 频率，还要实际配置 SysTick 重装值和时钟源，并避免与厂家毫秒延时实现重复占用。运行状态禁用阻塞式毫秒延时。

启用 Cortex-M4F 单精度 FPU，应用、内核端口、汇编和数学库的浮点 ABI 一致。GNU 可研究 -mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 与所选 float-abi；具体参数随 SDK 确认。快速路径使用 float，避免无意使用 double 和浮点格式化打印。异常延迟压栈、浮点上下文及嵌套中断对 PSP/MSP 的消耗都须实测。官方端口的浮点保存逻辑见[调度汇编](https://github.com/eclipse-threadx/threadx/blob/master/ports/cortex_m4/gnu/src/tx_thread_schedule.S)。

两路 inverter 的三相桥开关频率已定 20 kHz。以下仅作最初的性能验收预算：假设两路逆变和 PFC 的快速控制均以 20 kHz 更新，周期 50 µs、192 MHz 下约 9600 cycles；控制算法执行率与采样调度仍需验证，这不冻结 PFC 或制动的最终 PWM 频率。实际门极更新截止点可能早于周期末，仍需逐级核对。

| 处理 | 每 50 µs 的预算上限候选 |
| --- | ---: |
| 采样整理/公共处理 | 3 µs |
| 逆变 1 快环 | 8 µs |
| 逆变 2 快环 | 8 µs |
| PFC 快环 | 6 µs |
| 其他快中断开销 | 2 µs |
| 快路径合计 | 27 µs，约 54% |
| 内核及线程平均预算 | ≤8 µs，约 16% |
| 余量目标 | ≥15 µs，约 30% |

这些数值是测量后要满足或修订的目标，不能作为现有算法速度。用 DWT 周期计数与外部测量记录最长执行时间、入口延迟、PWM 提交时间和漏帧；验证三套控制、SPI、UART/CAN 满负载与故障同时出现的工况，不能仅用平均 CPU 利用率判定实时性。

## ADC、SPI 与 DMA

物理引脚与通道以[引脚草案 A](pin_assignment.md)为准。三路 ADC 共采 25 根模拟信号，不能为每套控制分别占用一套完整 ADC 状态机。快速控制仅消费带完整性标记、采样时间戳和序号的帧；旧帧不能当成当前电流使用。NTC 可低频采集，PFC 输入电压等信号的采样率由控制需求确定。

初次联调先用 ADC 完成中断直接读取结果，证明统一采样时序后再引入 DMA。厂家用户手册第 8 章说明循环 DMA 会静默覆盖、不产生通常设想的每轮完成中断；采用单次模式又需重新使能，因此不能直接套用其他 MCU 的循环半满/全满框架。

八路 DMA 的上限候选分配如下，初版不强制全部启用：

| 通道候选 | 用途 | 说明 |
| --- | --- | --- |
| 0/1/2 | ADC0/1/2 | 验证后启用；搬运完成与帧交接另行落实 |
| 3/4 | SPI0 RX/TX | 全双工各占一通道的保守预算 |
| 5/6 | SPI1 RX/TX | 同上；短编码器帧也可用受控中断方式 |
| 7 | UART0 RX | 需要时启用；UART TX 先用低优先级中断 |

CAN 初版用中断收发，不另占 DMA；若增加 FMAC、UART TX DMA 或更多传输，需重新分配。每个 DMA 通道同一时间只服务所配置的请求，不将多个并发外设随意并到同一通道。优先级、请求位、字节/半字宽度和地址递增按该芯片第 8/13/19 章核对，不把本表当作已验证 DMA 配置。

两路 SPI 若用于 FOC 角度反馈，交易调度属于控制时序的一部分；有硬性时限的读取不由低优先级 communication 线程临时发起。角度记录必须带时间戳、有效性和超时状态。编码器型号未定，SPI 时钟、帧长和读取频率暂不冻结。

## SRAM 与 Flash 预算

40 KiB SRAM 的规划如下；使用默认全数据 RAM 映射，暂不把 SRAM 改为代码加速区。若未来启用 CRAM，应重新计算剩余数据容量。所有数字是预算，最终以 map 文件和栈水位为准。

| SRAM 项目 | KiB |
| --- | ---: |
| 5 个应用线程＋timer 线程栈 | 9 |
| MSP/嵌套中断栈 | 3 |
| 内核控制块、队列控制与同步对象 | 3 |
| 三套控制状态、滤波与标定数据 | 9 |
| ADC/SPI 帧与交接缓冲 | 2 |
| UART/CAN/命令缓冲 | 3 |
| 故障与抽样诊断记录 | 2 |
| BSP/库其他全局变量 | 2 |
| 未承诺余量 | 7 |
| **总计** | **40** |

禁止隐式通用堆、无界日志、全速连续波形存储；按需抽样记录。每个对象只能归入一项预算，不能把栈或队列重复计算。调试期开启栈检查，测量 FPU 与最坏嵌套工况；预留 7 KiB 不等于允许任意增加线程。

256 KiB Flash 先按应用（含余量）216 KiB、未来启动区 32 KiB、参数区 8 KiB 作逻辑预算；启动区不是已经实现的 bootloader。应用内候选：BSP/ThreadX 48 KiB、算法/数学库 80 KiB、协议/状态机 48 KiB、诊断 16 KiB、余量 24 KiB。实际地址与擦除粒度随 SDK/链接脚本确认，不在此冻结分区。

## 数据所有权与状态机

communication 只提交经过范围校验的命令；supervisor 管理 DISABLED → CHECK → READY → RUN，以及 FAULT_LATCHED，异常需明确操作才能恢复，不自动重启。两路逆变和 PFC 各有状态，系统另有联锁状态；独立试验时不无条件互相依赖，整链联调时按母线建立关系配置启停顺序。

快环独占 PWM 比较值提交；线程仅更新请求快照。ENABLE 的置高由 supervisor 授权，故障快路径可随时拉低；故障处理同时撤销运行许可，线程不能用过期许可再次置高。更换板型、采样刻度和 PWM 模式只在功率级停机后进行。

共享结构采用有界、可证明的快照交接，包含发布序号、内存屏障及缓冲区复用规则。仅加 volatile 不构成完整同步；中断不能自旋等待被自己抢占的线程完成写入。读取不一致时保留上一份合法给定，样本失效则按超时策略停机。日志满时记录丢失计数，不阻塞快环。

看门狗由 supervisor 在确认快环帧序号、慢环和通信健康策略满足后统一喂；service/idle 不单独喂狗掩盖控制失效。Flash 擦写、参数保存和固件升级安排在功率输出关闭后执行，先验证该芯片擦写对取指和中断的影响。

## 移植与验证顺序

1. 补齐厂家 SDK/CMSIS、工具链、正式 ThreadX tag、链接脚本和启动文件，建立最小可复现构建。当前均未集成。
2. 先验证时钟、FPU、GPIO 默认态、SWD、复位、串口与看门狗，再接入内核 SysTick/PendSV/MSP/PSP。
3. 在 tx_application_define 创建静态对象，验证 1 kHz tick、优先级、BASEPRI 边界、堆禁用和栈检查；启动入口见[官方初始化说明](https://github.com/eclipse-threadx/rtos-docs/blob/main/rtos-docs/threadx/chapter3.md)。
4. 不接功率母线验证 PWM/ADC/SPI 时间关系和故障注入，再分别低压联调一套、两套逆变。
5. 待 PFC 功率板与门极时序明确后验证三套同步控制，并测满负载最坏时延与内存水位。

初始配置候选：TX_MAX_PRIORITIES=32、TX_TIMER_THREAD_PRIORITY=2、TX_TIMER_THREAD_STACK_SIZE=1024、TX_TIMER_TICKS_PER_SECOND=1000、启用栈检查；不定义 TX_TIMER_PROCESS_IN_ISR。应用与内核统一启用 TX_INCLUDE_USER_DEFINE_FILE，配置以所锁定版本的[tx_user_sample.h](https://github.com/eclipse-threadx/threadx/blob/master/common/inc/tx_user_sample.h)与端口说明为依据。线程规划通过不代表芯片性能或整体闭环已验证。
